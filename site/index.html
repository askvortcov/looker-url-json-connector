Any JSON API as a Looker Studio data source

A free, open-source community connector for HTTPS JSON APIs that take a key in a request header. It runs in your own Google account, so your token and your data pass through no third party.

Set it up Source code on GitHub

Not in the Looker Studio connector gallery yet: today you deploy it yourself from the source, in about ten minutes.

Why it exists

Looker Studio has no free, generic way to read a JSON API that needs an authorization header. The usual choices are a paid partner connector, or a service in the middle that receives your API token and your data.

  • Free and open

    Apache-2.0 source you can read in an evening. No account with us, no plan, no trial.

  • Nothing in the middle

    Requests go from Google Apps Script straight to your API. The project runs no server.

  • No database needed

    If your service can answer with JSON rows, it can feed a dashboard. No warehouse, no export job.

How it works

  1. Deploy the script to your Google account with clasp and open the connector in Looker Studio by its deployment id.
  2. Enter the key and the API URL. Looker Studio asks for the key in its own credentials dialog; the URL, an optional query string and the path to the rows go into the connector settings.
  3. Build charts. The connector detects the fields and their types from the response and passes the report's date range to the API.

An API that answers like this needs no settings beyond its URL:

GET https://api.example.com/metrics/v1?metric=dau&from=2026-11-01&to=2026-11-23
Authorization: Bearer <your key>

[
  {"day": "2026-11-22", "metric": "dau", "value": 120},
  {"day": "2026-11-23", "metric": "dau", "value": 123}
]

In Looker Studio it becomes a date dimension day, a text dimension metric and a number metric value.

Built to be safe with a token

  • The key stays yours

    It is stored in your private Apps Script user properties and sent only as the request header, only to the host you entered.

  • Public https only

    Plain http, local and private addresses are refused, and a redirect to another host is never followed.

  • Quiet errors

    Error messages say what to fix and never contain the key, the query string or a stack trace.

Details: security notes and the privacy policy.

Current limits

One GET request per query and no pagination yet. One key per Google account per deployment. Timestamps become dates. See the roadmap for what comes next.
